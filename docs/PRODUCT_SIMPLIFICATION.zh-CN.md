# 产品对照与操作简化

日期：2026-11-25。目标：普通用户和管理员都以菜单、表单和设备列表完成操作；网络参数由程序管理，特殊环境再展开高级设置。

## 可以参考哪些成熟产品

| 软件 / 项目 | 官方资料中的设计 | NetGo 采用的方向 |
| --- | --- | --- |
| Tailscale | 以身份和设备为中心建立对等网络；subnet router 连接不安装客户端的局域网设备，exit node 负责互联网出口。[S1][S2] | 把“访问办公室资源”和“使用办公室互联网出口”分开；客户端自动选择连接路径，用户不必理解每个中继地址。 |
| NetBird | Networks 组织资源、访问策略和路由节点；资源经策略授权后才能访问。自建指南集中引导部署，并列明公网域名和代理等前提。[S3][S4] | 最接近现有项目，继续复用已有 NetBird 集成；管理员围绕“开放什么、谁能访问”操作，用模板填写常见服务。 |
| RustDesk | 自建 OSS 后端把 ID / 会合 / 信令交给 hbbs，无法直连时交给 hbbr 中继；Web 控制台等集中管理能力需区分 OSS 与 Pro。[S5] | 远控列表直接提供查看、控制和断开；连接路径作为状态信息，避免用户自行拼接底层组件。 |
| MeshCentral | 在网页创建设备组，安装 Agent 后设备出现在管理列表；网页提供桌面、终端和文件管理。[S6] | 借鉴“设备列表 → 操作”的集中管理体验和清晰授权。NetGo 本轮仍是原生远控客户端，不宣称已有浏览器远控。 |

这些软件覆盖的范围不同。NetGo 同时包含局域网访问、账号授权、互联网出口和原生远控，适合借鉴各自的交互与职责划分，而不是将多个完整产品直接拼到一起。本次只借鉴设计，未复制第三方实现，也未新增依赖。

## 复杂度来自哪里

- 首次安装原来连续要求输入证书身份、Relay/STUN 地址端口、网卡、网段和站点 ID，普通部署也需要了解内部结构。
- VPS 原来重复询问三个主机和多个端口，容易把 LAN 身份误当成公网连接入口。
- 管理页原来暴露资源 ID、CIDR、协议、配置版本和手动应用按钮，创建常见资源要自行转换参数。
- 账号行同时展示限额、到期和多选权限，且每五秒刷新会替换正在修改的账号对象。

## 本轮已落实

1. **LAN 菜单按用途组织**：首次配置、状态、外网访问、添加客户端、高级设置、诊断和卸载；返回、输入结束和无效选择统一处理。
2. **首次配置自动检测**：列出正在运行且有可用 IPv4 的网卡和网段。单网卡可确认默认；多网卡必须按地址选择，不擅自猜测。自动生成独立站点 ID，默认使用同机地址与既定端口，高级选项保留域名、端口和网段编辑。
3. **VPS 推荐配对**：只需填写一个公网 IP / 域名，控制、隧道、Relay/STUN 使用预设端口。修改已有配置时默认保留自定义设置。特殊端口、三域名共用 443 位于高级流程。
4. **状态说明可达性**：区分内网地址、共享地址、域名和待实测 IP；不把服务运行、保存配置或导出文件等同于公网已连通。
5. **网页管理起步指引**：添加资源、创建账号并授权、导出所有平台使用的站点文件；原有后台自动应用策略保持生效，配置版本折叠，失败时显示重试。
6. **资源模板**：HTTPS、SSH、SMB、Windows RDP、Ping、旁路由出口及自定义；自动生成资源 ID，单台 IPv4 自动转换为 /32。带主机位的网段会提示正确网段而不是悄悄放大授权范围。RDP 明确区别于 NetGo 自带远控。
7. **账号权限编辑**：独立草稿、勾选资源、按需展开限额和到期时间；后台列表刷新不再覆盖草稿。账号与资源页面拆成独立组件，参数规范化留在共享 UI 模块。

菜单层只负责交互和收集配置；校验、证书、事务应用、回退与服务管理继续使用原有模块。菜单不直接拼 shell 命令或修改系统网络。API v2 与当前数据结构无需额外兼容层；没有为了调整界面而改动认证边界。

## 管理员现在的操作顺序

首次在 root 终端启动运行包的安装脚本后，程序打开菜单。日常用 ng / ngv 打开菜单；账号、资源和远控权限在网页中点击操作。当前尚未实现完全无终端的 Linux 首次安装，也没有网页写入 root 部署配置的接口。

- LAN：选择网卡 → 输入站点名称 → 接受推荐设置 → 自动生成证书 → 创建管理员。
- 外网：在“设置外网访问”中配对 VPS 或管理公网直达入口。VPS 配对仍需将节点包复制到 VPS 并导入菜单；路由器映射和云防火墙由所在环境配置。
- 日常：网页添加资源 → 创建账号并勾选权限 → 导出站点文件交给用户；用户导入后登录。手工配置保留为可选能力。
- 远控：在远程桌面页登记和授权设备，客户端选择目标；跨设备画面、键鼠、音频和网络恢复仍需实机验收。

192.168.18.220:10443 可以是正确的内网入口 / 站点证书身份，但不能直接作为外网可达入口。公网访问需要路由器映射后的真实公网候选，或已建立的 VPS 反向通道。仅填写 VPS 地址不会创建隧道。

## 后续设计边界

进一步减少“配对包复制”和客户端导入步骤，可研究有时效、可撤销且绑定站点公钥的邀请 / 配对流程。实现前必须明确初次信任和权限范围；不能通过自动接受网络下载的 CA 来省略安全步骤。此邀请流程、完整网页部署管理和全部原生客户端统一交互尚未在本轮实现。

ARM64 是部署目标，不是用户应理解的配置项。LAN/VPS 安装器识别机器架构并核验包内程序，提供 amd64 与 arm64 两种包。当前不包含 armv7。
