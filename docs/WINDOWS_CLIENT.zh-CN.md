# Windows 客户端使用说明

当前客户端为 0.3.0-dev 开发版。日常只有一个入口 **NetGo.exe**：主界面自动管理连接后台、网络准备及远控窗口。Windows 的完整跨设备远控、UAC/锁屏、多屏和长期运行仍待验收。

## 安装与首次连接

1. 从 [Windows client 工作流](https://github.com/sck03/NetGo/actions/workflows/build-windows-client.yml) 最近一次成功运行下载 Artifacts。解压外层归档，在 `dist/windows-client/` 找到 Setup 和绿色 ZIP。
2. 安装版双击 Setup，之后从开始菜单打开 NetGo；绿色版解压后打开 NetGo.exe。首次 VPN 网络授权由程序发起，按系统提示授权即可。
3. LAN 管理员在 `ng → 5) 导出客户端配置` 中导出 `NetGo-site.json`，发给客户端用户。当前公开配置也保存于服务端 `/etc/netgo/client-site.json`。
4. 在 NetGo 主界面点击“导入”，选取该 JSON。它包含公共 CA、入口、VPN 网关及中继信息，不包含账号密码、令牌或私钥。
5. 选择导入的服务器，输入管理员分配的账号和密码，点击“连接”。“通过旁路由访问互联网”默认关闭，只有获得对应账号授权后才能启用。

配置文件来自同一站点时，程序会核对版本和身份。管理员更换控制主机或 CA 后，应重新导入其提供的新文件，并确认身份变更。已经导入的 ID、控制身份和 CA 受保护，不能随意在编辑框里替换。

## 截图中的“新建服务器”怎么填写

普通用户使用“导入”即可。新建表单适合管理员已经提供完整参数、需要手工填写的情况；表单里的 `site1`、`control.example.com`、`100.96.0.1`、`relay.example.com` 都是示例，不能直接保存当作真实配置。

| 字段 | 内容和来源 | 不应填入的地址 |
| --- | --- | --- |
| 显示名称 | 自定义，例如“家里的服务器” | 不承担站点身份校验 |
| 站点 ID | LAN 导出文件中的 `ID`，必须与服务端相同 | 不要自创 ID 或默认沿用 `site1` |
| 控制网址 | 导出文件中的 `Origin`，例如 `https://192.168.18.220:10443` 或站点控制域名 | 不因使用 VPS 而改成 VPS IP、Relay URL 或 SSH 地址 |
| 直达入口 | `Candidates` 中 `Kind: direct` 的控制入口，格式 `主机:端口` | 不填 Relay 端口、STUN 端口或 VPS 的 frps 隧道端口 |
| 路由虚拟 IP | 导出文件中的 `GatewayIP`，即 LAN 路由节点的 VPN 内部地址 | 不填 LAN 服务器的 `192.168.*` 地址、VPS 公网 IP、旁路由 IP 或客户端自身 VPN IP |
| 证书信任 | 导入站点 JSON 会携带公共 CA；手工配置时可导入管理员给的公共 `ca.crt`/`pem` | 不导入 `ca.key`、服务器私钥或完整 VPS 配置 ZIP |
| 本地中继 | 导出文件中的 `LocalRelay`，填写 LAN Relay 主机名或 IP，例如 `192.168.18.220`；只用于本地路径识别 | 不加协议、端口，不填 VPS IP 或旁路由 IP |

“使用系统信任”表示使用 Windows 的证书信任。私有 CA 站点若尚未导入对应公共 CA，不能只保留这个选项。导入管理员提供的站点 JSON 会自动解决客户端所需的 CA 配置；管理浏览器的系统信任需另外设置。

### 控制网址为什么不改成 VPS

控制网址标识始终提供账号、权限和服务的 LAN 站点。客户端通过“直达入口”或“备用入口”决定实际连接到哪台机器，仍校验同一站点身份。

举例：

| 项目 | LAN 内连接 | 经 VPS 从外网连接 |
| --- | --- | --- |
| 控制网址 | `https://192.168.18.220:10443` | 仍为 `https://192.168.18.220:10443` |
| LAN 直达入口 | `192.168.18.220:10443` | 保留，连不上时自动尝试备用入口 |
| VPS 备用控制入口 | 站点文件可同时包含 | `203.0.113.10:24443`，`Kind: auxiliary` |
| 本地中继标识 | `192.168.18.220` | 仍标识 LAN Relay |
| VPS 中继标识 | 来自服务端配置 | `rels://203.0.113.10:28443`，位于 `AuxiliaryRelay` |

`203.0.113.10` 是文档示例 IP。你的真实值以管理员导出的 JSON 为准。外网 PC 的浏览器未必能直接打开 LAN 私有控制网址，但客户端可以通过已经导入的 VPS 备用入口连接该站点。

VPS 备用入口和备用中继不在普通新建表单里。管理员在 LAN 的 `ng → 7) VPS 设置与导出` 中配置 VPS，再用 `ng → 5) 导出客户端配置` 生成包含这些字段的 JSON。客户端导入即可；如需手工维护，“配置 → 高级配置”对应的字段是 `Candidates` 和 `AuxiliaryRelay`。

独立端口模式下，VPS `24443` 用于客户端备用控制，`27000` 用于 LAN 与 VPS 之间的隧道，`28443` 用于 Relay。不要将它们混填到“直达入口”。本地/VPS Relay 的实际连接地址和端口由服务端下发，“本地中继”本身不创建中继，也不决定选择哪台中继。

## 连接与权限

连接过程中按钮可取消；连接后用于断开。已有会话冲突时，仅在需要替换当前账号旧会话时勾选“替换旧连接”。

“可访问资源”显示获准的 IP/网段、协议和端口。连接 VPN 不会自动开放所有局域网设备，VPN 权限也不替代 NAS、SSH 或目标设备本身的账号。

旁路由 IP/DNS 在服务端设置，例如 `192.168.19.254`。管理员还须授予账号“互联网（旁路由）”资源；客户端开关只选择已授权能力。旁路由地址不填到新建表单的 VPN 网关或中继字段。

客户端采用可信服务端时间计时，不再因本机和服务端相差 30 秒而拒绝连接。证书有效期、签名、防重放和会话期限仍会检查。

## 页面与常用操作

| 入口 | 操作 |
| --- | --- |
| 连接 | 服务器、账号、密码、记住密码、替换会话、互联网模式、连接/取消/断开 |
| VPN 信息 | 实际控制候选、VPN 数据路径、虚拟地址、流量和错误 |
| 可访问资源 | 当前账号获授权的网络、主机、协议和端口 |
| 日志 | 查看连接事件，导出脱敏诊断 |
| 配置 | 导入/导出站点、手工新建/编辑、高级配置、删除和忘记密码 |
| 远程桌面 | VPN 连接后操作已有远控功能；完整跨设备验收尚未完成 |

勾选“记住密码”并成功连接后，凭据才写入当前 Windows 用户的 Credential Manager。启用自动连接前先成功保存凭据；忘记密码可从配置菜单操作。

关闭窗口默认保留托盘。托盘可打开窗口、断开或退出；退出会关闭当前连接和后台。安装版在系统“已安装的应用”中卸载。绿色版的网络准备器位于 `.netgo`，由主界面调用；普通用户不需要手工运行维护脚本或后台程序。

快捷键：Ctrl+O 导入、Ctrl+N 新建、Ctrl+E 编辑、Ctrl+L 日志、Ctrl+Q 退出。

## 排错

- `site_identity_mismatch`：站点 ID 与服务器不同，重新导入管理员提供的文件。
- 证书错误：检查控制网址是否被改成 VPS、公共 CA 是否已导入、系统日期是否在证书有效期内。
- 无法连接控制服务：核对控制入口端口；外网使用 VPS 时检查站点 JSON 是否包含备用入口。
- `internet_forbidden`：账号没有互联网资源授权，关闭互联网选项或由管理员授予权限。
- 一直“协商中”或无法识别数据路径：确认 VPN 网关及中继标识来自服务端，不是表单的示例值。
- 配置版本冲突：获取服务端最新导出文件；普通编辑不能绕过配置版本或证书保护。
