# Windows 与服务端稳定性重构（2026-11-27）

本轮以 `ffb34ff` 为基线，执行前一轮审查定位的修复。范围为 Windows 客户端、共享远控文件模块及 Go 服务端存储路径；保持现有原生窗口和 Vue 管理页设计。API v2 / schema 4 不增加旧版本兼容层。其他平台同步共享组件，但没有确认设备验收完成。

## 已修复的问题与模块边界

| 问题 | 当前实现与约束 |
| --- | --- |
| 引擎请求写管道阻塞，取消和退出失效 | `EngineChannel` 独立封装受当前用户 ACL 保护的异步命名管道。请求仍经子进程 stdin/stdout 分帧，秘密不进入命令行。锁等待、写入和读取共享 25 秒期限，20 ms 检查取消；撤销后收齐内核 IO 完成再释放缓冲。子进程挂入 Job Object 后才运行。 |
| Agent 崩溃后窗口不恢复、无法正常退出 | `AgentLifecycle` 在 UI 工作线程处理恢复；检查单例互斥对象所有权，只有旧 Agent 不存在或已终止才重启。状态、配置读取和退出可重试，连接等变更命令不自动重放。重启时执行网络清理；失败保留 `engine_cleanup_failed`，禁止假报退出成功。后台未响应仍有界报错，不强杀存活 Agent。 |
| 手动配置首次连接出现版本冲突 | 普通新建使用只读引导版本 0。认证成功后同步服务端正式版本、候选入口、网关 peer 和 DNS。已发布配置继续执行同版本冲突、回滚及站点信任检查；共享契约覆盖手动引导到正式版本及拒绝替换信任域名。 |
| 切换站点时复用旧远控窗口 | 窗口类和远控单例包含站点 ID，主窗口按持有的进程句柄管理子进程。切换先通知旧子进程退出，计时器回收后启动新站点；5 秒仍未停止则终止本程序拥有的 Job。应用退出和站点切换保留下次登录恢复设置；用户主动停止共享仍关闭该设置。 |
| 软件编码在显示分辨率减小时中止 | 软件 BGRA→NV12 同时支持缩小与放大，继续使用会话初始协商画布，与 GPU 的全画面缩放及归一化输入一致。宽高比变化会拉伸到固定画布，重新连接可重新协商；本轮未引入动态尺寸协议。 |
| 查看端文件 IO 卡住媒体、文件超时结束远控 | `AsyncExchange` 独立线程拥有 `Exchange` 状态机及本地文件句柄。媒体线程只交换有界请求、响应和事件；仍最多 8 个在途请求。10 秒命令超时结束当前传输、发送取消并丢弃迟到 ID，后续命令可继续。Windows 对慢 IO、取消和退出请求同步 IO 取消，析构 join 后才释放所有者；文件 flush 后发布前重新检查取消和下载能力。 |

无人值守的凭据检查从窗口消息线程移到共享工作线程，取消或关闭窗口后不能重新启用恢复设置。外部 C ABI 保持不变，事件仍在 `ng_remote_client_run` 调用线程交付，不从文件线程回调平台 UI。

主机命令队列在 8 个普通请求之外预留 1 个取消请求位置；取消确认也超时后，查看端暂停新命令，直到迟到确认表明旧传输已经清理。这个边界避免磁盘积压把取消变成协议错误，媒体与授权循环仍继续运行。

## 性能与维护性

- Windows 解码直接消费收到的压缩字节，移除构造临时 Packet 的复制；读取解码器输出时直接锁定 Media Foundation 缓冲，复用 NV12 帧。查看端最多保留三个共享 BGRA 画面缓冲，UI 持有的画面不会被覆盖，积压时只丢弃已解码的旧画面。CPU 色彩转换与 GDI 呈现仍保留，没有宣称 GPU 查看链路已完成。
- `VPNUpdate` 用于获取/撤销租约及启动、退出清理；`RemotePolicyUpdate` 用于主机登记和授权变更。两者读取活动远控依赖，不再解码关闭历史和远控幂等表。修改账号/设备所有权仍走完整图事务；远控签发仍读取保留历史，以维持 generation 防重放和容量约束。
- 网关变更保留 SQL 提交边界、失败关闭及周期修复。本轮没有删除宿主 nftables 检查，也没有改动未经真实 Linux 验证的权限边界。
- 管理网页已有账号、资源、六项远控权限、会话停止、历史、审计和诊断适配。本轮无新增业务 API；Go→TypeScript DTO 检查、网页生产构建及相关前端回归通过。维护命令、其他平台适配和有效历史文档继续保留。
- `prepare-native.ps1` 识别清理后残留的空目录树，只初始化自己的 Git 检出并校验固定提交，不再把父项目的 HEAD 当成 OpenSSL。清理脚本新增本轮下载与验证目录，仍检查仓库边界、链接、跟踪文件、嵌套仓库改动和活动进程。

本轮减少热点路径的复制和历史解码，没有用代码行数替代模块化，也没有测量完整业务的 CPU、内存或延迟百分比。

## 必要验证

使用固定 Go 1.27.4、Node 26.13.1、OpenSSL 4.1.0、项目锁定的 Vue/TypeScript/Vite 依赖和本机 MSYS2 UCRT64 编译器。

- Windows 原生完整编译通过。定向 CTest：native-lifecycle、native-core、native-ipc、native-profile-contract、remote-display-layout、remote-video-codec、remote-files、remote-async-exchange、remote-client。
- 引擎回归使用不读取子端的真实管道，验证 2 MiB 写入的超时和取消、未返回数据的读取取消及管道再次使用；Agent 恢复回归注入消失/存活无响应情形，确保变更命令不重放。
- 文件回归覆盖上传/下载内容完整性、回调线程归属、排队取消和退出清理、命令超时及迟到响应后继续处理新命令。首轮异步测试的夹具曾在目录句柄关闭前清理目录，修正作用域后复验通过。
- 取消预留位置补充后再次编译并定向复验 remote-host、remote-files、remote-async-exchange；与此前九项合计覆盖十个 CTest 目标。
- Go：`go test ./internal/store ./internal/session ./internal/remote ./internal/api ./internal/site` 与 `go test ./internal/contracts ./internal/site` 通过；对活动事务、提交回滚、路由 revision、保留历史、撤权与在途获取、退出保护、主机替换和授权轮换运行定向 race 回归。
- 网页：`vue-tsc --noEmit && vite build` 通过；remote、remote-pagination、session-state、resource-contract 四个测试文件共 9 项通过。
- PowerShell 构建准备/清理脚本语法检查及清理预览通过。
- Linux amd64、CGO 关闭，`go build -o .cache/refactor-server/ ./cmd/...` 通过；该检查覆盖服务端和维护入口编译，不替代 Linux 内核运行验证。
- `prepare-native.ps1 -SkipOpenSSLBuild` 在原空目录树（含空 `.git` 残留）上实际复验，固定提交和依赖校验通过。修改文档的本地链接检查与 `git diff --check` 通过。

最终 Windows `NetGo.exe` 为 7,417,344 字节（约 7.07 MiB），低于项目 10 MiB 预算；PE 导入仅为系统 DLL/UCRT。该大小不包含 NetBird、Wintun 或完整安装包。验证程序随后按用户要求作为可重建产物清理。

本轮没有运行全仓库完整测试、全平台构建、上游完整发行包测试、真实 Linux nftables/conntrack 内核验收或长期压力测试。Windows 测试覆盖本机合成编解码和协议，不等同于两台物理设备的完整远控验收。Windows 的 IO 取消仍依赖底层驱动响应；不会通过脱离线程或提前释放缓冲来假装取消完成。
