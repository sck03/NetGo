# 远控状态、授权与旁路由诊断验证

日期：2026-11-25（Asia/Shanghai）。接续“优化远程桌面与服务器访问配置”。本轮使用新接口，无旧客户端回退分支；LAN 服务端、管理网页与客户端需要同步更新。

## 实现

- 远控库存由服务端根据共享状态、心跳、VPN 租约、账号状态和活动会话计算主机状态；有效能力为主机能力与未过期账号授权的交集，自身设备不开放自控入口。
- Windows、Linux、Android、macOS、iOS 列表只显示可连接且获授观看权限的主机；共享查看器建立媒体连接前再次检查。主机忙碌返回明确的 409 / remote_host_busy。
- 管理网页不依赖客户端墙上时钟判断主机是否在线；授权支持编辑和到期设置，只显示已实现能力。后端拒绝主机未支持的授权。后台刷新不会清除操作错误或覆盖编辑草稿。
- 旁路由菜单拆为配置草稿、DNS 探测与网络检查模块；保留已有 DNS，检测全部主备服务器，共用 5 秒期限。查询失败或空结果不会被当作普通 DNS，失败不保存配置。
- 新增 ng 第 7 项 / ng check-network：读取网卡、路由归属和 DNS，报告 Fake-IP 模式不匹配；不修改路由、系统 DNS 或服务。
- 实机发现 VPN 维护循环内的探测 / 路由等待会阻塞远控请求；Go 与 Windows 改为独立有界请求工作线程，断开时取消 / 收拢工作后再释放凭据。凭据轮换与在途签名请求同步，Windows 控制入口选择支持并发读取。

## 实机与交付记录

VPS 临时客户端已通过公网辅助控制入口与 Relay 连接，真实 Fake-IP HTTPS、旁路由互联网出口、授权 LAN HTTPS 和未授权 LAN 端口阻断均已得到成功结果。首次 HTTPS 请求出现 TLS EOF、后一次 DNS 查询超时，后续完整重试通过；本记录保留这些初次失败，不将其解释为长期稳定性通过。

原客户端远控心跳出现一次 20 秒请求期限耗尽。审阅发现远控队列由 VPN 维护循环串行执行，探测 / 路由恢复会阻塞它；改为独立工作线程后，真实注册 → 心跳失联 → 心跳恢复 → 关闭共享全部通过。修复后客户端 SHA256：2ca3bdae01240f5e606a8d17a81a8041047168bd758cc98ea30c3caebd3a5e76。

### 首次请求异常调查

保留已发生的 TLS unexpected EOF 和 DNS 超时。NetBird 日志确认一次对 192.168.19.254:53 的上游查询等待 4 秒后失败；当时命名空间 DNS 配置及引擎挂载中的配置均指向正在监听的本地 NetBird DNS。后续分别查询 A / AAAA，得到 NOERROR：A 返回 Fake-IP，AAAA 返回无记录。受限包头观测确认成功复测时 DNS 请求经过 VPN、LAN 转发和旁路由返回，三轮重连的请求全部通过。

这些结果不足以确定初次失败发生在哪一段，也未证明重复路由选择是原因，因此未据此修改路由或 DNS 重试逻辑。另一次 LAN 本机直接请求 Fake-IP 超时，其路径不同于 VPN 客户端的受管转发，未计入通过指标。首次 DNS / TLS 偶发失败仍是开放问题，不能用后续成功覆盖。未修改旁路由设备或两端系统默认网关。
