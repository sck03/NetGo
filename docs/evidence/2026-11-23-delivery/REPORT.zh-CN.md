## 时钟与请求预算修复

Windows W32Time 起初报告未同步；两个 NTP 地址请求超时。Windows 与 NTP 正常的 Debian 的时钟差约 64 秒。用户通过管理员脚本依据经过 SSH 主机身份验证的 Debian 样本校准后，同次 SSH 往返内两端秒数差不超过 1 秒。未放宽接口防重放的 30 秒窗口。

服务端健康响应增加当前 Unix 时间；Windows、Linux CLI 与管理网页在发送密码前检测偏差，给出明确校时提示。Go、原生 C++ 与前端回归覆盖未来时钟、正常时钟，以及偏差时不发认证事务/密码。

Windows 认证读取原本使用固定 3 秒 socket 超时，提前截断总预算 20 秒的请求；以签名响应延迟 3.5 秒复现 FAIL，改成剩余总预算后 PASS。健康探测仍为 3 秒，单次普通 API 请求仍为 20 秒，上限由单调时钟和 socket 关闭保证；不会无限提高超时以掩盖故障。Linux/上游的独立探测、认证、RPC 与清理预算继续分别验证。

## 公网已验证子项

公网高位端口 FRP 控制转发保留原站点 TLS 身份。7 项检查通过：可信健康、私有路径拒绝、原生管理员登录、签名管理请求、真实 Dex 刷新、凭据旋转、刷新后的签名请求。

在实验客户端阻断全部 UDP 和所有直达地址后，公网备用控制及 VPS Relay 的 TCP 内容校验、UDP 应用传输、未授权端口拒绝、UDP 阻断计数和清理均通过。仅给该命名空间到一个公网 VPS 添加精确的临时 SNAT 规则，并在结束时删除。VPS 的现有 80/443 和 SSH 服务保留。实际 443 出站限制、运营商多 WAN/DDNS、公开 CA 续期与 72 小时尚未宣告通过。

IP 形式站点经 FRP 时 TLS ClientHello 可没有 SNI；Caddy 增加固定站点的 default_sni，仍验证站点证书，没有关闭 TLS 校验。自定义 CA 的 frpc 信任使用专门的可读 trust.pem，CA 私钥及控制证书私钥未复制到 VPS。

## Windows 实测闭环

23 项实际检查全部 PASS：原生密码登录、TCP 校验、1664 字节 UDP 数据及 SNAT 回程、未授权端口拒绝、站点凭据隔离、脱敏诊断、默认路由保留、断开阻断、保存密码重连、稳定 peer 与新 generation、忘记密码、取消不迟到重连、删除测试站点和恢复路由/DNS。安装到 Program Files 的核心 SHA-256 与本轮验证产物相同。

Windows 大 UDP 报文的故障来自首片未建立 userspace conntrack。只为包含完整传输头的发送首片登记状态，回包仍受已有入站连接与分片判决检查保护；孤立分片及错误端口继续拒绝。修复后原来的 1664 字节实测 PASS，上游分片安全及竞态回归 PASS，没有缩小报文规避问题。

## 项目目录测试与主机维护

用户要求后续尽量不占用系统 C 盘。Windows 构建脚本将 Go 编译/模块缓存、npm 缓存与临时目录统一放在 `E:/NetGo/.cache/toolchain`。已将原缓存移到项目目录，保留内容。Windows 的 C 盘测试服务已卸载，改由用户在管理员窗口启动项目目录内的前台核心；客户端数据、核心状态和日志位于 `.cache/windows-project`。该模式用于本次开发测试，产品安装器的系统服务模式仍单独提供。

跨盘迁移后修复目录所有者与私有 ACL，使普通用户后台能够使用自己的数据目录。前台模式没有新建系统服务；测试完成后断开隧道。Windows 凭据仍由系统 Credential Manager 管理，测试账号的密码与设备键通过 Forget/Delete 清理。
