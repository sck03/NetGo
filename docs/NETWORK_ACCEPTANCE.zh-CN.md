## 1. 统一环境与记录规则

角色：L=本地 Linux；C1/C2=远程客户端；D=LAN 设备；V=可选 VPS；R=控制公网/NAT 的实验路由器。每次报告记录 Linux/Windows/内核、软件精确版本、配置 hash、拓扑和网络条件。

国内动态公网基线使用实际放行的高位端口，示例为控制 10443、Relay 18443。不能把本地 443 被运营商限制误判为系统必须改用 443；分别记录入站限制、NAT 映射和出站限制。A10 可以用本地高位端口 + VPS 443 的混合模式测试。

P0/P2 可以使用最小原生客户端验证协议与网络，但不能替代正式 Windows 交付；P3/P4 必须使用实际安装包重新运行相关用例。仅标准浏览器认证可以建立底层基线，不计入原生账号密码登录通过。

每个用例的报告存储于未来 `docs/evidence/<版本>/<用例ID>/`，至少包含：

1. 用例 ID、需求 Rxx、执行日期时间与时区、执行者、PASS/FAIL/NOT-RUN。
2. 初始状态：设备是否新注册、token 是否有效、缓存候选、DNS 解析、已配置 Relay/STUN。
3. 操作与故障注入时刻；恢复步骤必须先准备好。
4. 控制请求实际目的地、TLS/站点身份、数据路径、业务访问结果。
5. 相关日志、路由、防火墙计数与脱敏抓包；大文件的源/目标校验和。
6. 耗时和资源统计，失败原因与可复现步骤；不能仅附 UI 截图。

抓包和诊断不得携带密码、token、私钥、完整真实业务内容。使用专门测试数据，保留复现需要的地址角色和时序。

## 2. 路径判定原则

- 公网/打洞直连：核心状态显示 P2P，且 L 与 C 之间存在匹配的直接数据流；V 不承载该业务规模的数据流。
- 本地中继：核心状态与本地 Relay 日志确认使用 L 的 Relay；流量不经过外部 V。
- VPS 中继：核心状态、V Relay 日志和流量计数一致，业务字节经过 V，最后仍到 L 和 D。
- 控制经 VPS 不等于数据中继；控制流量可以一直存在。
- 两端 NAT 打洞失败必须由真实网络限制或受控故障制造。强制 Relay 选项只验证 Relay 可用性，不算自动退回中继验收。
- 清空客户端状态要使用专门测试 profile/虚拟机快照；不删除真实用户凭据。设备冷启动与仅保持已有隧道分别记录。

## 6. 指标采集和判定

1. 故障时钟统一，记录故障注入 t0、首次恢复控制 t1、首次成功业务 t2。分别报告 t1-t0 与 t2-t0。
2. 每类恢复至少 20 次计算 P50/P95、最差值和失败率；样本过少不宣称 P95 达标。
3. DNS 更新分为提交、独立解析器可见、客户端解析更新三个时点；应用可控时间与 DNS 延迟分开。
4. 性能对照固定 CPU、网卡、MTU、目标服务、加密、负载和链路；不能拿直连 NetGo 对比中继 ocserv。
5. 资源记录启动、稳定、负载峰值和 72 小时趋势；单个峰值不能证明泄漏或无泄漏。
6. 不达时间指标时记录实际值与原因，不能改计时起点美化结果。功能失败或安全约束失败不得按性能例外放行。

发行通过条件：R01–R12 均有对应证据；当前声明支持的环境中 A01–A33 通过；未支持的环境明确从兼容清单移除，用户核心需求相关用例不能移除。原生密码认证、无 VPS 冷启动、VPS 全停重连、自动备用、服务端撤销是阻断发行项。
