# 远控授权票据格式（API v2 草案 1）

日期：2026-11-23。用于接通 Go 服务与 C++ 主机门禁；API v2、主机登记、持钥证明及持久防重放尚未启用。格式实现和跨语言验证不代表主机已可远控。

票据为固定 **168 字节**。前 104 字节是规范消息，后 64 字节为 Ed25519 签名。签名覆盖完整消息；算法固定，不接受客户端提供算法、公钥或可替换 issuer。主机从受信任站点配置取得 32 字节 Ed25519 公钥，站点注册/换钥另行认证。二进制编码避免字段顺序、重复 JSON 键、浮点数和各语言大整数差异。API 传输封装可以使用严格无填充 base64url，解码后必须恰好 168 字节。

| 偏移 | 长度 | 字段与约束 |
| --- | --- | --- |
| 0 | 8 | ASCII `NGRMTK01`：协议域和版本；未知版本拒绝 |
| 8 | 32 | `binding_digest`：受信任上下文的 SHA-256，禁止全零 |
| 40 | 16 | 随机 `session_id`，禁止全零；由服务端生成 |
| 56 | 8 | `generation`，大端无符号整数，非零 |
| 64 | 8 | `policy_revision`，同上，非零 |
| 72 | 8 | `sequence`，同上，非零；同会话续租严格递增 |
| 80 | 8 | `issued_unix_ms`，大端 UTC 毫秒，非零 |
| 88 | 8 | `expires_unix_ms`，必须大于签发时间，差值最多 30,000 |
| 96 | 4 | `capabilities`，大端位集合；必须有 VIEW，拒绝未知位 |
| 100 | 4 | `consent_required`，大端，只有 0/1 |
| 104 | 64 | 标准 Ed25519 签名，对偏移 0..103 的原始字节签名 |

能力位：VIEW=1、INPUT=2、AUDIO=4、CLIPBOARD=8、UPLOAD=16、DOWNLOAD=32。不存在依靠隐式枚举顺序推导的位。签名后任何一个字节变化、截断、附加尾部、错误密钥或非规范签名都必须拒绝。C ABI 调用者先初始化输出结构的 size/version；该头部有效时，失败清零全部 claims，ABI 不匹配时保持调用者内存不变。

真实服务端必须用密码学随机源生成非零 128 位 `session_id`，作为初次授权的一次性标识；续租保持该 ID 并严格增加 `sequence`。测试样本的确定性字节不用于生产 ID 或密钥。

`binding_digest` 的原像为 ASCII 域 `NetGo remote binding v1` 后加一个 NUL，再按下面顺序连接字段。每个字段先写 4 字节大端长度，再写原始字段字节：站点 ID、受信任站点 Ed25519 公钥、用户 ID、控制设备 ID、控制设备公钥、被控设备 ID、被控设备公钥、被控启动实例 ID。ID 为 1..128 字节的 ASCII `[A-Za-z0-9._:-]`，密钥恰为 32 字节且非全零，启动实例是 16 字节随机数且非全零。不做大小写折叠、Unicode 归一化或别名推断。主机必须用认证上下文独立重建摘要，不能直接信任控制端提供的摘要。

验证顺序：限制输入长度 → 确认格式/版本 → 使用站点固定公钥验签 → 解码与结构校验 → 主机重建并比较绑定摘要 → 门禁检验时间/代次/权限 → 主机注册表原子消费初次会话标识 → 本地同意 → 开启获准工作者。取消与并发撤销必须能在外部验签后再次阻止提交。注册表和门禁提交由主机协调，不允许消费/启动的竞态产生第二个活动会话。

这份票据只证明服务端授予了指定会话，**不能单独证明对端持有控制设备私钥**。传输握手还须证明私钥持有并把证明绑定本会话、主机随机挑战、启动实例及通道 transcript。禁止把此票据当成可转发的 bearer 登录令牌。没有完成持钥证明和跨会话/重启防重放之前，产品不得开放监听或公布远控 capability。

Go 使用标准库 Ed25519/SHA-256。C++ 解码和 binding 编码不自行实现密码算法；OpenSSL 适配为独立可选链接目标，仅主机/连接后台可使用，门禁与 UI 不因此链接 TLS/crypto。Android/Apple 可替换系统密码适配但必须通过同一组正反用例。测试向量密钥只用于固定公开测试，不作为运行时密钥或默认配置。
