# 2026-11-26 全项目审查后的修复与收敛

基线提交：d1eaf59d589ecf10bc8af934443f56971ac90f37。当前仍为 0.3.0-dev / API v2 / SQLite schema 3。本轮执行此前审查确认的问题与有边界的重构，不增加旧接口、旧数据库迁移或旧客户端回退。

## 已修复问题

| 问题 | 修复后的行为 |
| --- | --- |
| 主机快照跳过待处理票据导致 remote_renewal_pending 断开 | 按序号推进最近的服务端授权；快照领先时可直接采用更新票据，快照落后时也能先推进已经核实的序号，保留更晚的待确认请求。每张对端票据先验签并核对身份、代次、序号、版本与权限收缩，实际生效继续经过原有门禁。保留 5 秒快照时效、6 秒失联门禁与票据到期检查。 |
| 慢上游阻塞其他账号和设备撤权 | 账号创建按 alias/email 预约，清理按实体去重；预约表只在内存登记时持锁，结束即释放。账号修改、本地撤权和其他实体操作不等待上游 HTTP。清理仍先持久化撤权，再执行有超时和退避的上游请求。 |
| 管理员在排队/上游等待期间被撤权，旧请求仍可能提交 | 管理上下文携带已认证凭据；账号、设备、资源和管理员会话撤销在写事务内复核当前凭据、账号状态和角色。创建失败保留上游补偿，审计记录实际操作者。后台清理使用系统身份。 |
| Web 操作期间换页漏加载、旧查询覆盖新数据 | 页面读取与 mutation busy 分开；换页立即失效旧查询并加载，首次加载有提示及重试入口。写操作完成后强制发起新查询，已有页面刷新不销毁编辑草稿。 |
| ARM64 被诊断误报不支持 | Doctor 与运行监控共用 platform.Supported，支持 Debian 12/13 的 amd64 和 arm64。 |
| 移动端 UTF-16 长度与核心 UTF-8 限制不一致、删除风暴丢输入 | 核心统一提供 8192 UTF-8 字节上限；Android/Apple 明确提交文字，输入法组合期间 Android 不提交，队列拒绝时保留草稿。退格和回车以按下/释放原子批次入队。文本背压不再清掉此前已排队文字；普通输入过载仍释放按键并拒绝新事件。 |
| Apple 同名下载冲突、命令被拒绝却无提示 | 每次下载使用独立目录；拒绝提交时删除空目录，取消/失败事件清理本次未完成目录。已完成文件保存在 Documents/NetGo Downloads，可分享或显式删除。命令失败有反馈，状态轮询不再每两秒覆盖操作提示。 |
| 桌面文件操作的反馈不一致 | Windows 命令队列满时提示，取消优先处理；Windows/Linux 提示下载不得覆盖已有目标。平台预检查改善反馈，共享文件核心仍负责原子防覆盖。Android 提交失败或等待就绪超时释放暂存上传状态，允许再次选择文件。 |

“已入队”不等同于远端已经执行。断线、失焦、超过 1 秒的陈旧输入和过载仍按安全门禁丢弃/释放；不为了保证输入送达而无限重放。

## 模块与资源占用

- internal/coordination 管理短期工作预约；internal/authorization 管理写事务的管理员复核；上游 IO 不再借用服务级全局锁。
- internal/store/remote_inventory.go 按普通用户可见主机加载完整授权依赖，包括参与会话的其他控制端，保留准确的忙碌状态。管理员仍需要全局管理视图；本轮没有引入任意截断或缺少客户端适配的分页协议。
- 设备分页只读取本页的租约和账号标签；55 条记录的回归夹具中，末页实际加载 5 个设备、5 个租约、5 个账号。
- 特权辅助客户端复用 HTTP transport 和连接，结束生命周期时关闭空闲连接。VPN 写入和网关生效仍保留同一提交屏障，未把网关 IO 移出撤权保护范围。
- C++ 主机/控制端复用各自的控制响应缓冲，容量与 Go 的 4 MiB 响应上限一致，消除每次心跳/续期重新分配缓冲。此选择减少分配次数，但保留缓冲会增加空闲驻留量；未声称它减少所有场景的峰值内存。
- Go 客户端发布 profiles_revision；成功导入或自动同步站点配置才推进。Android/Apple 首次读取及修订变化时刷新列表，Apple 内容未变不写 UserDefaults。
- Linux 服务启动/网络组件安装、Linux/Windows 登录启动设置、Apple 下载目录管理分别独立；Linux 删除重复 Base64 实现，复用共享的规范编码和解码。
- init-admin 显式写 max_sessions=1，删除 MaxSessions=0 的旧默认补偿、UI 重复默认值、无生产调用的 Store.RemoteView 和已失效的 /netgo-ui/* 代理规则。/admin/state 全量入口及 /me 仍有验收消费者，保留；Debian nftables 输出差异适配也仍有效。

数据库保持单写者与完整策略提交约束。本轮减少已确认热路径的读取/分配，没有整体替换存储引擎，也没有据此给出未经测量的性能提升比例。

- Go：accounts、devices、store、session、remote、api、client、diagnostics 定向 race 通过；新增慢上游期间另一实体撤权、创建期间管理员被撤销、创建补偿、同实体清理去重、远控依赖完整性与分页回归。client/operations 后续相关检查通过。
- Linux ARM64：server、ctl、helper、client-service 交叉编译通过；不代表已在 ARM 设备部署运行。
- Web：认证、查询、资源、远控及会话状态测试通过；新增忙碌期间换页和保存后覆盖旧读取的回归，最后三项会话状态回归通过。最终 TypeScript/Vite 构建通过，JS 116.48 kB / gzip 41.96 kB，CSS 11.32 kB / gzip 3.31 kB。
- Windows / 共享 C++：Windows 编译通过；session、ticket、host、files、watchdog、input 六项定向测试通过。host 用 7 秒测试票据、400 ms 请求/响应延迟和连续四次续期覆盖领先与落后；最终变更后再定向验证 host/input。
- Android：Kotlin 和 ARM64 JNI 编译通过。使用现有 Go 绑定的二进制接口做编译验证；没有生成完整 APK，也未重新生成移动绑定。本轮修改的共享 Go 客户端源码由 client 测试与 ARM64 编译覆盖，正式构建必须重新生成 AAR。
- 工具：6 项部署模板回归通过；macOS/iOS 工程生成结果都包含新增下载模块。清理脚本先预览，再实际执行并核对保留文件。
- Apple 与 Linux 桌面原生 UI：本机缺少 Xcode/Linux 图形构建环境，只做接口、源文件引用与生命周期检查，未声称通过本轮平台编译或实机操作。没有完整跨设备音视频、WAN 故障矩阵、72 小时稳定性或全部平台测试矩阵。
- Linux 查看器及 macOS/Linux 主机未实现的音频能力保持原范围，不新增虚假能力声明。
