## 修复与模块边界

| 问题 | 最终行为与落点 |
| --- | --- |
| Go 与 Windows 对站点名称、网关和 CA 的校验不一致 | 客户端均验证名称 1–256 UTF-8 字节、IPv4 网关、可解析且最多 32 KiB 的 CA。共享 profiles.json 覆盖空名称、无效/缺失/IPv6 网关和无效 CA。服务器初始化配置允许网关尚未分配；正式导出必须完成初始化，Web 返回可识别的 site_not_ready。 |
| 创建账号补偿失败后没有重试记录 | accounts/create.go 负责创建与补偿；store/account_cleanup.go 保存独立任务，后台按退避重试并跨重启保留。补偿前检查是否已有本地账号；若本地提交已成功，仅清除任务。404 视为上游已经清理。 |
| 管理页会话列表随设备分页，漏掉后续设备上的有效会话 | sessions 与 devices 分别分页，租约列表使用与摘要相同的有效性条件。SessionPanel 自主管理双游标、查询取消和撤销操作；ListPager 复用分页交互。资源搜索明确标注“本页”，账号授权仍加载完整资源选项。 |
| Windows 保存密码未绑定站点信任 | remembered_login.cpp 集中处理绑定与读取，Go 使用 site.TrustIdentity。协议、站点 ID、规范化主机名和 CA 必须匹配；端口、候选地址、显示名可更新。Windows 显式替换信任时清理旧密码和该站点的自动恢复标记，缺少绑定字段的开发期凭据不再复用。 |
| macOS 自动恢复绕过手动断开排序 | DesktopConnectionCoordinator 统一 connect/restore/disconnect/disableUnattended。连接代次在入队前更新，过期恢复与回调丢弃，断开操作保持执行顺序。网络安装提示在 IPC 队列外等待，不能阻塞断开。 |
| macOS 仅查看也强制辅助功能权限 | 屏幕录制允许后即可共享，只有已授予辅助功能时才登记输入能力；媒体打开时再次校验权限。未授予输入权限时显示仅查看提示，重新开启共享后更新能力。 |

账户创建和上游服务之间不具备分布式原子事务。上游未返回新 ID 就断线、本地磁盘完全无法写入等情形仍需要运维排查，不能用补偿机制宣称这些故障被完全消除。数据库保存的是补偿元数据，不保存初始密码。

API 服务只维护一份账号服务和设备服务实例，初始化时注入；删去重复的懒加载实例。删除没有产品调用方的 `/netgo/v2/me` 和缺少 section 的全量 admin/state 分支，网络验收工具同步改为当前接口及逐页读取。诊断导出改用摘要查询，不加载完整用户/设备对象。移除 Vite 的 `/netgo-ui` 无用代理，并补充服务端 CI 对 Vite/TypeScript 配置变更的触发路径。

本轮保持现有管理页卡片、按钮和操作反馈规范，未引入新的视觉系统。没有因为当前 Windows 主机不编译某个平台就删除其适配层。CLI 的证书、密码重置、备份、部署维护等仍是有效功能。

## 续租性能

`store.VPNRenew` 保留全部网关租约及相关所有者、当前资源、活动远控依赖；不再加载闲置账号/设备、无关资源、全部凭据及操作记录。网关应用仍在原有数据库事务边界内，保留撤权一致性、容量检查和失败后关闭访问的行为。没有放宽 nonce 持久化防重放或改用不持久的缓存。

Windows amd64、i5-9400F、内存 SQLite，200 个账号/设备/资源/凭据、2 个租约、1 个活动远控依赖，单轮 `BenchmarkVPNRenewSnapshot -benchtime=300ms`：

| 同一数据集 | 单次耗时 | 单次分配 | 分配次数 |
| --- | ---: | ---: | ---: |
| 先前全量加载范围 | 14,013,419 ns | 1,236,379 B | 14,122 |
| 本次依赖范围 | 951,590 ns | 35,766 B | 442 |

这是状态读取/克隆/比较的微基准，不包括上游 Peer 验证、真实磁盘同步及 nftables 调用，不代表生产吞吐或端到端延迟。大量同时在线租约仍需要处理完整网关集合。媒体/文件共用 TLS 队列、远控管理选择列表规模、平台原生 UI 大文件仍可在实际测量后继续优化；本轮没有将尚未实施的 QoS 或大规模架构重写计为已完成。
