# ADR-0005：原生多平台与可选远程桌面

日期：2026-11-23。状态：产品边界已确定；媒体依赖待 RD1 原型通过后冻结。

用户将远程桌面及各平台原生客户端加入当前交付，允许使用全新接口与数据库，不要求兼容旧开发数据。原 VPN 只提供客户端到 LAN 路由节点，不能直接当成任意两设备的远控拓扑。

采用统一产品与独立权限模块。Windows 使用 C++/Win32，Android 使用 Kotlin，Apple 使用 Swift，Linux 桌面使用 C++/GTK。媒体核心以 C++ 实现并提供版本化 C ABI；JNI/ObjC++ 只桥接，不复制会话、输入门禁和协议逻辑。平台 VPN 与远控媒体是独立适配任务。

先验证操作系统提供的窄媒体适配，再与 MiniRTC 候选比较；CrossDesk 参考桥接/集成，Aspia 参考主机服务与权限，RustDesk 保留备选。必须在 Win32/Kotlin 上完成实际帧/输入/音频及 overlay 直连/中继/撤销原型，才将候选写入正式发行依赖。暂不把任何候选称为已经集成。

服务端统一切换 v2/schema 2，不做 v1 双写或兼容层；切换前归档旧开发状态，新目录初始化，保留完整回退能力。主机独立校验会话票据、权限、启动实例和本地租约；不能依靠仅位于 Linux 网关的 nftables 来保护 peer-to-peer 远控。

2026-11-23 v2.1 补充：共享会话门禁先作为零第三方运行依赖的独立 C++/C ABI 库实现；认证票据验证、平台时钟、媒体与输入通过窄接口接入。默认要求本地同意；观看、输入、音频、剪贴板、上传、下载各自检查。只有已经绑定目标及启动实例的认证票据可以开启会话，续租不可增加初始权限或复活已结束会话。媒体原型是单独退出条件，不因门禁测试通过而冻结媒体依赖。

代价是增加五个平台的 SDK、权限、签名、构建和设备验收，以及主机端常驻服务的维护。移动端先作为控制端；不承诺 iOS 系统级无人值守被控。旧版本阶段退出不代表新增阶段通过。

v2.2：站点身份、网络通道和远控会话保持独立状态机，通过类型明确的事件协调退出、撤权与路径恢复。媒体候选必须复用 NetGo 身份与已授权传输，无法移除的重复账号/信令依赖是淘汰条件。Windows DXGI 采集先独立验证，不把 GPU/COM 指针放入共享 ABI，不以采集成功冻结整套媒体依赖。

v2.2 票据实现：Go 标准库签发、独立 C++/OpenSSL Crypto 验签、固定公开跨语言测试向量；零依赖门禁和 Win32 UI 不链接该适配。认证状态由主机协调器重建；签名成功不代替持钥证明、策略重验或一次消费。协议见 [远控票据](../REMOTE_TICKET.zh-CN.md)。
