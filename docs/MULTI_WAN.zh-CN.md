# 多 WAN：H3C 路由器与 NetGo 的职责

当前设备信息由用户提供：**H3C 新华三 MSR3610-X1-DP，接入 2–3 条宽带，可使用负载均衡和主备切换**。本文件约定产品与路由器之间的接口。实际 Comware 版本、接口名、拨号、策略路由及 NAT 配置尚未提供，也未进行实机测试；不使用未经核对的型号专用命令修改路由器。

## 谁来处理

| 工作 | 负责方 |
| --- | --- |
| PPPoE／动态地址获取、识别每条 WAN 的真实地址 | H3C 路由器 |
| 每条公网线路到 Linux 的端口映射与入站限制 | H3C 路由器 |
| 按连接保持出口、入站回包从原 WAN 返回、线路探测与策略切换 | H3C 路由器 |
| 每条 WAN 的 DDNS 更新 | 优先由路由器更新；或向 Linux 提供可信的逐 WAN 地址文件 |
| 站点身份、账号、资源权限、会话租约 | Linux NetGo |
| 多入口探测、保留 TLS/issuer、失败恢复和 VPS 备用 | NetGo 客户端与既有核心适配 |

Linux 网卡在内网通常只看到路由器这一个默认网关。一次外部 IP 查询只反映这次请求的出口；负载均衡下重复查询可能获得不同 IP。不能让这种结果轮流覆盖三个 WAN 共用的一个 DDNS 记录。

## 两种部署方式

**主备方式**：为 NetGo 的控制、STUN/Relay、frpc 等连接选择一个优先出口；线路失效时按路由器的健康检测切至备用线路。普通内网上网可以继续使用负载均衡。多条仍可入站的线路都可配置为客户端候选；尚未启用或正在拨号的备用线暂时探测失败即可。

**按连接负载均衡**：不同连接可以分配到不同 WAN，同一个 TCP/UDP 会话须保持出口一致；入站 DNAT 对应的回包必须从原 WAN 返回。不要把同一个 UDP/QUIC/WireGuard 会话的连续数据包在公网地址间来回分配。NAT 映射发生变化时，核心需要重新协商，客户端记录恢复过程。

两种方式都能与 NetGo 的多个入口候选配合。单条数据连接通常使用一条实际路径，不能从线路数量推导单连接带宽叠加，也不承诺更换公网 IP 后所有已有 TCP 业务无中断。

## 地址与端口示例

使用 `examples/site-multiwan.json`。三个候选分别为 `wan1.site.example:10443`、`wan2.site.example:10443`、`wan3.site.example:10443`；只有两条线时删除 wan3。站点逻辑地址仍为 `https://control.site.example:10443`，证书使用控制域名。IP 或候选变化不改变账号、site_id 和 issuer。

| 入口 | H3C 映射到同一 Linux | 说明 |
| --- | --- | --- |
| 每条 WAN TCP 10443 | Linux TCP 10443 | HTTPS 控制入口；也可按线路选择不同外部高位端口并修改候选 Address |
| 可用 Relay 入口 TCP/UDP 18443 | Linux TCP/UDP 18443 | WS/QUIC；LocalRelay 稳定域名应指向当前可用线路 |
| UDP 3478 | Linux UDP 3478 | STUN；受限线路可能不可用 |
| UDP 51820 | 路由节点实际固定 UDP 端口 | 按核心实际监听及映射验证，不能只打开端口就假设发布正确 |

当前控制入口支持最多八个候选，足以容纳三条 WAN 和可选 VPS。恢复探测覆盖全部直达候选；同一个可用候选连续确认三次且满足冷却期后，才从健康备用入口切回直达。WAN1 不可达时仍检查 WAN2/WAN3。桌面状态与 CLI 状态包含当前候选 ID。

本地 Relay 仍为一个服务，使用稳定域名指向当前可用线路；其 DNS 更新、缓存淘汰、NAT 映射和数据路径切换须按 A06/A08/A32 实测。三条控制入口通过不等于三条数据路径均已验收。无实际公网入站能力的 CGNAT 线路不能作为直达入口，可供 Linux 向 VPS 出站使用。

## DDNS 获取方式

优先在 H3C 或其受信管理程序中，按 WAN1/WAN2/WAN3 分别更新独立记录。每个记录有独立名称与 RecordID，线路停用时按已审阅策略撤销或保留为暂不可达候选。需要同时更新本地 Relay 的稳定入口，不能只更新控制地址。

如果路由器不能直接更新所用 DNS provider，可使用 `examples/ddns-wan-file.json`：受信管理程序定期、原子地写入 `/run/netgo-ddns/wan1.ip`，内容只有该 WAN 的一个公网 IP。为其他线路使用独立文件、域名和 DNS RecordID。文件应位于受保护目录，由管理员管理，不允许组或其他用户写入。

`AddressFile` 与 `Witnesses` 不能同时配置；文件默认超过 300 秒未更新即拒绝发布，保留原 DNS 记录并告警。私网、CGNAT、地址族错误或多地址文本均被拒绝。当前提供 Cloudflare DNS 更新适配；没有自动接管 H3C、抓取管理页面或推测各 WAN 地址。

示例运行：`netgo-ddns --config /etc/netgo/ddns-wan1.json`。每个实例管理一个记录；由管理员配置相应服务实例。路由器直接管理 DDNS 时，不再启动会写同一记录的 Linux 实例。

## 在 H3C 上验收

1. 记录 Comware 版本、各 WAN 接口、真实公网地址／CGNAT 状态、入站限制和当前负载策略。
2. 分别从外部网络访问三个候选，抓包核对入站 WAN、Linux 目标及回包 WAN，验证 TLS 仍对应控制域名。
3. 在主备方式下逐一断开优先线路，验证 DDNS、控制、数据、续租及恢复；记录实际耗时和被中断业务。
4. 在负载均衡方式下验证长连接和 UDP 会话的出口稳定性，再重复故障；不能仅用网页访问成功作判断。
5. 恢复 WAN1 时验证防抖，避免三条线路状态变化造成频繁迁移；再测试有／无 VPS 两种情况。
6. 用 A04/A05/A07/A08/A09/A22/A32 记录结果。当前这些真实 H3C 场景均为 NOT-RUN。
