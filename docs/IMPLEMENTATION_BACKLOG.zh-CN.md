# NetGo 实施任务清单

修订：2026-11-23。当前执行方案 v2.2；代码基线 0.2.4-dev，下一目标 0.3.0-dev。远控与 Windows/Android/macOS/iOS/Linux 原生客户端已纳入本轮，详见 [REMOTE_NATIVE_PLAN](REMOTE_NATIVE_PLAN.zh-CN.md)。新 API/数据库不要求兼容旧开发格式，切换前须归档。统一体验、模块边界和 I01–I10 组合验收见 [集成契约](INTEGRATION_CONTRACT.zh-CN.md)。

本轮已补齐两份独立安装脚本、完整 Linux 原生包路径和紧凑 Windows 客户端，并修复真实部署、身份刷新、状态隔离、内核撤销、升级权限及并发协调问题。最终安装版本通过生命周期 19、维护 34、公网中继 18、本地中继 15、十会话 32 项复验；历史 API 28、隔离隧道 48 与 Windows 23 项另行保留。最终构建、依赖错配修复和待验条件见 [接续报告](evidence/2026-11-23-continuation/REPORT.zh-CN.md)及 PROGRESS；未标记生产发行完成。

以下 P0–P4 保留 VPN 基线的位置和退出条件。LAN 已是 Debian 13，公网 VPS 已提供。旧公网 Relay 最终复测失败已定位为 controller 公钥顺序问题；补丁后在原失败顺序下 18 项公网实测通过，本地 Relay 15 项也通过。Windows 新核心、最终源码/产物绑定及其他环境仍需分别记录。Windows 11、Apple/Android/Linux 桌面设备、真实多 WAN/DNS、跨用户/休眠与 72 小时单独登记。

## 使用规则

1. 按依赖推进；用户已授权无实验环境时继续源码、自动验证和验收工具。G1–G6 未通过仍不能宣布真实阶段退出或生产发行。
2. 每项任务提交变更、验证记录、未解问题；有网络行为的任务必须有运行证据。
3. 一轮可连续推进多个阶段；每项交付分别记录源码、验证和未通过条件，供独立审阅。
4. 所有配置示例引用锁定版本；不得偷偷使用官方云、默认公共 Relay 或已有设备缓存掩盖独立性问题。
5. 引用 Axx 为 `NETWORK_ACCEPTANCE.zh-CN.md` 中的用例；用例结果只能填通过/失败/未测，不能把计划当结果。

## 变更与评审模板

每个 issue/PR 使用以下字段：

- 任务 ID、目标用户行为、关联需求 Rxx。
- 前置任务与选用版本；需要改变的接口/配置。
- 实施范围和文件；新增依赖及权限。
- 验收用例 Axx、环境、实际结果与证据目录。
- 升级/兼容/回退影响。
- 未解决问题、下一步、是否满足退出条件。

完成一个任务不自动意味着整个阶段通过；阶段退出以主方案的门槛和网络证据为准。
